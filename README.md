# WITRN 风扇统一控制台（W96D / NEW W96D / W96D Pro）

把 **老版 W96D（USB/HID）**、**NEW W96D（BLE）**、**W96D Pro（BLE + 快充）** 三个硬件版本收进**一个单文件网页工具**，并附上完整逆向文档、官方小程序抓包与可复跑的回归测试。

- 工具版本：`v20260925g`（改完记得 `Ctrl+Shift+R` 强刷）
- **OTA 刷机已在真机验证通过**（2026-09-25，安卓手机 + Chrome 安卓：639 块 / 81764B / 13.3s，设备收尾回 `02` 后重启）
- 纯前端单文件，无构建、无依赖；需要 **Chrome / Edge**（iOS 不支持 Web Bluetooth）

```
git clone http://zqyfn.hcmedia.asia:20011/zqyhqw/Witrn-Fan-Control.git
```

## 快速开始

1. 用 **Chrome / Edge** 打开 `W96D统一控制台.html`（可直接本地文件打开，无需服务器）；
2. 按硬件版本连接：
   - **NEW W96D / W96D Pro** → 「连接蓝牙」，在**页面内**弹出的列表里选 `W96D…`（不要用系统蓝牙界面配对）；
   - **老版 W96D** → 「连接HID」，选 `DeepFan`。安卓 Chrome 需先开 `chrome://flags` → `web-hid-on-android` → Enabled；
3. 连接后即可用：风扇开关/切档/转速、自然风曲线（画布编辑后上传）、档位标定、Turbo、定时、灯光、蓝牙休眠、电池与状态遥测、W96Pro 快充实验；
4. **固件升级**见下一节；页面底部是统一通信日志（可见原始字节与解码）。

## ⬆ 固件升级（OTA）

> ⚠️ **务必先读**：`0x87` 之后设备应用区**已被擦除**，此时**不要断电、不要关页面**（全程约 15s）。
> 任何一步失败，工具都会明确告知"**是否已擦除**"：`0x87` 之前失败 ⇒ 应用区完好，直接重试；`0x87` 之后失败 ⇒ 设备停在 DFU 阶段，重新连接后再刷一次即可。
> **强烈建议先点「🧪 干跑」**：只走到"已进入传输阶段"，**不发 `0x87`、不擦除**，用来确认整条通路。

### 步骤

1. 蓝牙连接 NEW W96D / W96Pro → 打开**设备信息页** → 卡片 **⬆ 固件升级 OTA**；
2. 选择固件 `.up`（本仓库 `rom/W96D_V13.up` 即官方 V1.3，与官网 `W96DN_V1.3.zip` 逐字节一致）；
3. 点 **🧪 干跑（不擦除）** → 应停在「已在传输阶段（页 4096B）」；
4. 点 **⬆ 开始升级** → 确认弹窗 → 进度条走完 639 块；
5. 设备自动重启，等 5~10s 重新连接，工具会**自动回读并显示版本**。

### 设备侧流程（抓包实证）

```
0x0F/0x8F GET_SN → 0x8A GET_VERSION → 0x85(→01 应用态) → 0x84(→02)
→ 0x8F「切换」★ 必须紧跟 0x84 的应答、在同一条连接上立刻发（实测 59ms），不等断链
→ 设备停 BLE → 链路约 5s 监督超时断开（reason 0x08）→ 重连（MTU 243→247）→ 重新订阅 FEE2
→ 0x85(→02 传输阶段) → 0x8C(→05 00 10，页 4096 ⇒ 块 128B)
→ 0x81 + 文件头 96B（整帧 102B → 02）→ 0x87(→02，约 1.3s)
→ 0x02 + 128B × 638 + 末帧 100B（共 81764B，无逐块回执，约 18~20ms/帧）→ 0x88(→02) → 0x0B 复位
```

### 失败了怎么判读

| 现象 | 判定 | 怎么办 |
|---|---|---|
| 干跑停在"已在传输阶段（页 4096B）" | 通路正常 | 可以正式刷 |
| `0x88` 首次无应答 | **正常**（设备在写最后几页 + 校验，可能远超抓包的 133ms） | 工具会自己重试 3×20s；真机上第 2 次就拿到了 `02` |
| 最终提示"已回到应用模式（0x85→01）" | 固件已生效 | 无需处理 |
| 最终提示"仍停在传输阶段（0x85→02）" | 本次写入未被接受（很可能丢块） | 把**帧间隔**从 20ms 调到 **30~40ms**，重新连接后再刷一次 |
| 回读版本超时 | 设备还在重启 | 等 10s 后点「连接蓝牙」，看设备信息页版本 |
| 版本号没变 | 本次是**同版本重刷**（V1.3→V1.3） | 正常，直接看风扇功能是否可用 |

**两个可调项**：`帧间隔`（默认 20ms，抓包实测官方小程序 ≈18ms）、以及是否先干跑。
`S.ble.lastDevice` 会记住设备句柄，切换/重连不需要重新扫描（设备广播全程不变，`|DFU` 标记**不能**当作"已进 DFU"的判据，判据只有 `0x85` 的 `01/02` 与 MTU 的 `243/247`）。

## 抓包解析工具

```bash
node tools/parse_hci_log.js "BT_HCI_*.cfa" [--full]
```

输出：**连接与链路事件**（连接/断开原因、连接参数=监督超时、MTU 协商、CCCD 订阅）、**设备广播**、**DFU 命令 → 应答时序表**（含每条延迟与解掩码后的应答）、**数据阶段统计**（帧数/字节/间隔/速率）、句柄统计、完整写入/通知序列、≥20B 大帧字节。

设备通知帧按 `CRC8_TABLE[key]` 解掩码（key 每帧随机），解析器会顺带做 CRC 校验 —— 实测该抓包 **673/673 条帧 CRC 全部通过**。

## 常见问题

- **选不到设备／列表为空**：蓝牙必须在**页面内**的搜索按钮里选，系统蓝牙配对界面看不到；设备名形如 `W96D_000123`。
- **iOS／Safari**：不支持 Web Bluetooth，用不了；安卓 Chrome、桌面 Chrome/Edge 均可。
- **老版 W96D（USB 线）**：走 WebHID，安卓需开 `web-hid-on-android` flag；协议是 ASCII `CMD=value,`。
- **`FEE1.readValue()` 报 `GATT operation not permitted`**：设备声明可读但 ATT 层拒绝，属正常；**所有应答都走 FEE2 通知**。
- **同版本能重刷吗**：能。官方 bootloader 不拒绝同版本（抓包里小程序就是在 V1.3 上重刷 V1.3）。
- **想把版本号 +1 做测试包**：`node -e 'const fs=require("fs");const b=fs.readFileSync("rom/W96D_V13.up");b[0x4d]=0x0e;fs.writeFileSync("rom/W96D_V14_test.up",b)'`（头 96B 变化不改固件体，但会改变解锁帧的 CRC —— 工具会按文件重新计算，无需手工处理）。

## 踩过的坑（一句话版）

1. **`0x8F` 的时机**：必须在 `0x84` 应答后**同一条连接上立刻**发，等断链重连后再发就无效（设备只当普通 SN 查询）。
2. **CRC8 表里两个错值（真凶）**：官方网页表把下标 **120/202 误写成 200**（真值 102/101）。短帧两表恰好同值 ⇒ 控制命令一直正常；**长帧（102B 解锁头、134B 数据帧）CRC 全错 ⇒ 设备静默丢弃**。这就是"102B 帧怎么发都没反应"的原因，与帧长/写入类型/时序都无关。
3. **应答别乱丢**：解锁帧的真实应答是 **`02`**（`expect` 列表曾漏掉它），且个别通知的末尾校验字节与算法不符 —— 现已"结构完整即宽容采用"并留痕。

细节、证据与逐轮复盘见 `逆向分析与统一工具方案.md` §2.4.0 / §2.4.0.1。

## 关键协议速查

- **帧格式**：`55 | key | len16LE | payload | CRC8`，CRC 覆盖 `frame[0..len+4)`，poly `0x3B`、**非反射**、初值 `0x89`；**key 必须为 0**。
- **设备→主机**：字节（≥2）与 `CRC8_TABLE[key]` 异或（key 每帧随机），CRC 对**解掩码后**的帧计算。
- **服务/特征**：`FEE0` / 写 `FEE1` / 通知 `FEE2`（与沁恒 CH592F 官方 BLE OTA profile 同 UUID，但命令层是 WITRN 自研）。
- **控制命令**：`0x04/0x84` 进 DFU、`0x05/0x85` 查阶段（`01` 应用 / `02` 传输）、`0x07/0x87` 开始收数、`0x08/0x88` 结束、`0x0A/0x8A` 版本（`04 0d`）、`0x0C/0x8C` 页大小（`05 00 10`）、`0x0F/0x8F` SN（`0a` + LE32）、`0x0B` 复位（无应答）。
- **数据命令**：`0x81` 解锁 + 96B 文件头、`0x02` 写 flash（地址设备端自增）。
- 完整表见 `协议文档_W96D_BLE.md`。
